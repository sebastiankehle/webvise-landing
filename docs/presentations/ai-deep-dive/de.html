02 / Kontext

Warum gerade jetzt?

Der Wendepunkt

Wir haben den Punkt überschritten, an dem AI ein Experiment war. AI ist Infrastruktur geworden. Jede grosse IDE hat AI-Features. Terminal-Agents arbeiten autonom. Die Frage hat sich verschoben: nicht mehr "Sollen wir AI nutzen?" sondern "Wie schnell können wir adoptieren?"

Die Tools sind reif. Die Modelle sind gut genug. Die Integration in bestehende Workflows funktioniert. Was fehlt, ist eine strukturierte Einführung - und genau darum geht es heute.

03 / Evolution

Drei Wellen der AI-gestützten Entwicklung

Jede Welle hat die Rolle des Entwicklers fundamental verändert. Wir sind mitten in Welle 3.

Welle 01

Autocomplete

2021-2023. GitHub Copilot bringt AI in den Editor. Zeilenvervollständigung, Boilerplate. Der Entwickler bleibt am Steuer, AI ist ein besseres IntelliSense.

Welle 02

Chat & Copilot

2023-2025. ChatGPT, Claude, Cursor. Konversationen über Code, Multi-File-Kontext. Ganze Funktionen beschreiben und generieren lassen.

Welle 03

Autonome Agents

2025-heute. AI-Systeme, die planen, Tools nutzen, testen, deployen. Nicht ein Prompt, eine Antwort - sondern ein Ziel, viele Schritte. Das ist jetzt.

Der entscheidende Unterschied: In Welle 1 und 2 reagiert AI auf den Entwickler. In Welle 3 agiert AI eigenständig - plant, iteriert, korrigiert sich selbst.

04 / Tool-Landschaft

AI Coding Tools 2026

Co

GitHub Copilot

Breiteste Adoption, solide Autocomplete-Qualität. Agent Mode seit 2025, wirkt aber nachträglich angefügt. Für einfache Vervollständigung gut - bei komplexen Aufgaben schnell am Limit.

Cu

Cursor

VS-Code-Fork mit nativer AI. Starkes Multi-File-Editing, guter Codebase-Kontext, Composer für komplexe Aufgaben. Aktuell eine der besten IDE-Erfahrungen.

Cl

Claude Code

Terminal-basierter autonomer Agent. Plant, implementiert, testet eigenständig. Exzellentes Codebase-Verständnis. Volle Git/Shell/API-Integration. Selbst-hostbar.

Wi

Windsurf

AI-First-IDE mit Flows für Multi-Step-Aufgaben. Niedrige Einstiegshürde, gutes Kontext-Management. Solide Alternative zu Cursor.

Cx

Codex CLI

OpenAIs Terminal-Agent. Cloud-Sandbox-Execution, OpenAI-Ökosystem. Noch relativ jung im Vergleich zu Claude Code.

Ge

Gemini CLI

Googles Terminal-Agent. Grösstes Kontextfenster (1M+ Tokens), Google-Ökosystem. Kostenloses Tier verfügbar.

06
06 / AI Agents

Was ist ein AI Agent?

Ein Chatbot antwortet auf Fragen.
Ein Agent erledigt Aufgaben.

1

Zielverständnis

Versteht komplexe Ziele, zerlegt sie selbstständig in Teilschritte.

2

Tool-Nutzung

Greift auf Dateisystem, APIs, Datenbanken, Browser, Terminal zu.

3

Iteration

Prüft Ergebnisse, korrigiert Fehler, versucht Alternativen.

Der Agent-Loop

1. Ziel verstehen
2. Plan erstellen
3. Tools auswählen
4. Ausführen
5. Ergebnis prüfen
6. Korrigieren oder abschliessen
↻ Wiederholen bis Ziel erreicht

Anders als ein Chatbot gibt sich ein Agent nicht mit der ersten Antwort zufrieden. Er iteriert, bis das Ziel nachweisbar erreicht ist.

07
07 / MCP

Model Context Protocol - USB-C für AI

MCP ist ein offener Standard, der definiert, wie AI-Modelle mit externen Tools kommunizieren. Ein Protokoll, alle Tools.

Vor MCP

  • Jedes Tool eigene Integration
  • Keine Standardisierung
  • Kein Austausch zwischen Tools

Mit MCP

  • Ein Protokoll für alle
  • Einmal bauen, überall nutzen
  • Kein Vendor-Lock-in

Für Unternehmen: MCP-Server für interne Systeme werden einmal gebaut und von allen AI-Tools genutzt. Keine doppelten Integrationen.

MCP-Server in der Praxis

Datenbank-Server
PostgreSQL, Redis, Elasticsearch - sicherer AI-Zugriff
Git-Server
Repository-Historie, Branches, Pull Requests
Jira/Linear-Server
Tickets lesen, erstellen, Status aktualisieren
Monitoring-Server
Grafana-Dashboards, Logs, Alerts analysieren
Browser-Server
Webseiten navigieren, UIs testen, Daten extrahieren

08 / Mein Setup

Claude Code + oh-my-claudecode

Claude Code

Läuft im Terminal. Zugriff auf das gesamte Projekt-Dateisystem, Git, Shell-Kommandos und MCP-Server. Mein primäres Entwicklungstool.

  • Versteht die gesamte Codebase
  • Erstellt Commits, Branches, Pull Requests
  • Führt Tests und Builds aus
  • Greift auf Datenbanken und APIs zu (via MCP)

oh-my-claudecode (OMC)

Eine Orchestrierungsschicht auf Claude Code. Koordiniert spezialisierte Agents für verschiedene Aufgaben - automatisch.

  • Multi-Agent-Koordination
  • Parallele Ausführung
  • Spezialisierte Rollen (Architect, Reviewer...)
  • Skills-Integration

Das ist kein Demo-Setup. So liefere ich Code - bei luca und bei webvise-Kundenprojekten.

09 / Spezialisierte Agents

Agent-Katalog

Jeder Agent hat eine klare Rolle. Wie ein Team aus Spezialisten, die parallel arbeiten.

△

Architect

Strategische Architektur-Entscheidungen. Read-Only. Prüft Pläne bevor Code geschrieben wird.

■

Executor

Fokussierte Implementierung. Arbeitet parallel an unabhängigen Aufgaben. Schnell und präzise.

◆

Code Reviewer

Detaillierte Reviews mit Severity-Rating. Findet Patterns, die Menschen übersehen.

✓

Test Engineer

Test-Strategie und TDD-Workflows. Schreibt und validiert Tests automatisch.

⚠

Security Reviewer

OWASP Top 10, Secrets-Detection, unsichere Patterns. Automatisierte Security-Checks.

★

Verifier

Evidenz-basierte Completion-Checks. Tests bestanden, keine Regressionen, Deployment OK.

10 / Workflow-Beispiel

Von der Anforderung zum Deployment

// Anforderung: "Implementiere User-Authentifizierung für die API" 1. Planner → Analysiert bestehende Architektur, identifiziert Auth-Patterns 2. Architect → Reviewt Plan, empfiehlt JWT + Session-Strategie 3. Executors → Arbeiten parallel: ├ Agent 1: Auth-Middleware + Route Guards ├ Agent 2: User-Model + Migration └ Agent 3: Test-Suite + Dokumentation 4. Reviewer → Prüft Code-Qualität, Security-Implikationen 5. Verifier → Alle Tests grün, keine Regressionen, merge-ready

Zeitersparnis: ~45 Minuten für eine Aufgabe, die typischerweise 1-2 Tage dauert.

Qualität: Jeder Schritt wird von einem spezialisierten Agent geprüft. Menschliches Review bleibt Pflicht.

11 / Skills

Wiederverwendbare Agent-Fähigkeiten

Skills sind Markdown-basierte Anweisungen, die Agents spezifische Fähigkeiten verleihen.

  • Portabel - Claude Code, Cursor, Copilot, 19+ Tools
  • Versionierbar - in Git, teilbar über Teams
  • Komponierbar - Skills rufen andere Skills auf

skills.sh Ökosystem

Offener Marktplatz für AI-Agent-Skills. Statt dass jedes Team eigene Prompts schreibt, gibt es eine wachsende Bibliothek wiederverwendbarer Fähigkeiten.

Für Unternehmen: Einmal einen Standard-Skill erstellen, und jeder Entwickler nutzt ihn - unabhängig von IDE oder AI-Tool.

Praxis-Beispiele

webvise-conventions

Tech-Stack, Design-System, Code-Patterns. Jeder Agent kennt unsere Standards.

webvise-qa

webvise-deliver

6-Phasen Workflow: Discover, Plan, Build, SEO, QA, Deliver.

Enterprise-Skills

Coding-Standards, Checklisten, Onboarding. Versioniert, für alle Teams.

13 / Ehrliche Einschätzung

Was AI kann - und was nicht

Glaubwürdigkeit entsteht durch Ehrlichkeit. AI ist kein Zauberstab.

AI ist stark bei

  • Code-Generierung und Boilerplate
  • Test-Erstellung und Coverage
  • Dokumentation generieren
  • Refactoring und Code-Migration
  • Pattern-Erkennung und Security-Scans
  • Dependency-Management
  • Code-Review-Unterstützung

AI braucht Menschen für

  • Architektur-Entscheidungen
  • Business-Logik und Domänenwissen
  • User Research und Produktstrategie
  • Edge-Case-Beurteilung
  • Team-Dynamik und Kommunikation
  • Ethische Abwägungen
  • Kreative Problemlösung auf hohem Niveau

Die besten Ergebnisse entstehen, wenn man AI wie einen sehr fähigen Junior-Entwickler behandelt - schnell, gründlich, aber braucht Richtung und Review.

14 / EU AI Act

EU AI Act: Was Sie wissen müssen

In Kraft seit August 2024, volle Anwendung ab August 2026.

Minimales Risiko

Die meisten AI-Coding-Tools: Autocomplete, Refactoring, Dokumentation. Keine besonderen Anforderungen, aber Transparenzpflichten.

Begrenztes Risiko

Agent-Systeme, die eigenständig deployen oder Infrastruktur-Entscheidungen treffen. Transparenz- und Dokumentationspflicht.

Hohes Risiko

AI in sicherheitskritischen Anwendungen. Wenn AI-Code in Prüf- oder Zertifizierungssoftware fliesst. Menschliche Aufsicht erforderlich.

Empfehlung: Applikationen nach Risikoklassen klassifizieren. Richtlinien pro Risikoklasse definieren. AI-Governance-Board etablieren, das Standards setzt und überwacht.

15 / Datenschutz

DSGVO, Datenflüsse & Anbieter

Wo gehen die Daten hin?

Wenn Entwickler AI-Tools nutzen, wird Quellcode an den Anbieter gesendet. Das ist relevant, wenn:

  • Code personenbezogene Daten enthält
  • Proprietäre Geschäftslogik betroffen ist
  • Regulatorische Vorgaben gelten

Empfehlungen

  • API-Zugang nutzen (kein Training auf Ihren Daten)
  • Data Processing Agreements abschliessen
  • Code-Scanning vor dem Senden (keine Secrets, keine PII)
  • EU-Hosting-Optionen prüfen

17 / Nachvollziehbarkeit

Audit-Trails & Governance

Nachvollziehbarkeit ist nicht optional. AI-generierter Code muss denselben Standards entsprechen.

G

Git-Integration

Alle AI-Änderungen gehen durch normale Git-Workflows. Branches, PRs, Reviews. Nichts umgeht den Prozess.

T

Co-Author-Tags

AI-generierte Commits werden markiert (Co-Authored-By: Claude). Volle Transparenz, welcher Code von welchem Tool stammt.

R

Review-Pflicht

Kein AI-Code geht ohne menschliches Review in Produktion. Derselbe Standard wie für jeden Entwickler.

L

Logging

Welches Modell, welcher Prompt, welcher Output. Für kritische Systeme vollständig dokumentiert.

Q

Test-Standards

AI-Code erfüllt dieselben (oder höhere) Test-Anforderungen. Coverage-Ziele gelten unverändert.

P

Tooling

Git-Hooks für Co-Author-Tags, CI/CD-Pipelines die AI-Code flaggen, Custom MCP-Server für Logging.

18 / Adoption

Crawl - Walk - Run

Strukturierte Einführung. Schritt für Schritt, messbar, kontrolliert.

Phase 01 / Crawl

Erfahrung sammeln

Monate 1-3. 5-10 Entwickler.

  • Cursor oder Windsurf (niedrige Hürde)
  • Code-Completion, Docs, Unit-Tests
  • Basis-Richtlinien definieren
  • Entwickler-Zufriedenheit messen
Phase 02 / Walk

Standards etablieren

Monate 4-9. 50-100 Entwickler.

  • Claude Code für komplexe Aufgaben
  • Erste MCP-Server und Skills
  • AI-Richtlinie, DPA mit Anbietern
  • Proxy-Layer für Logging
Phase 03 / Run

AI als Standard

Ab Monat 10. Alle Teams.

  • Multi-Agent-Workflows
  • Automatisierte QA-Pipelines
  • Governance-Framework, Audits
  • ROI pro Team messen

20 / Ausblick

Was kommt als Nächstes?

Kurzfristig (2026)

  • AI-Agents Standard in jeder IDE
  • MCP als De-facto-Standard
  • Lokale Modelle erreichen Cloud-Qualität
  • Enterprise-Features bei allen Anbietern

Mittelfristig (2027)

  • Multi-Agent-Teams als Normalität
  • AI-gestützte Legacy-Migration im grossen Stil
  • Spezialisierte Branchenmodelle
  • Compliance-Checks direkt in AI-Workflows

5 Empfehlungen

  1. Jetzt starten. Die Lernkurve ist flacher als gedacht.
  2. Klein starten. Ein Pilot-Team, ein Tool, klare Metriken.
  3. In Governance investieren. Jetzt einfacher als später.
  4. Know-how aufbauen. Wissen, nicht nur Lizenzen.
  5. Ergebnisse messen. KPIs ab Tag 1.

Die Frage ist nicht ob,

sondern wie schnell.
