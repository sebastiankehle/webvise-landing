03 / The AI Landscape

Three Waves of AI-Assisted Development

From autocomplete to autonomous agents. The pace of change outstrips every previous technology adoption cycle in software.

Wave 01

Autocomplete

2021-2023. GitHub Copilot brings AI into the editor. Line completion, boilerplate generation. Helpful but limited to single lines and functions. The developer stays fully in control at every step.

Wave 02

Chat & Copilot

2023-2025. ChatGPT, Claude, and specialized assistants. Conversations about code, multi-file context. Cursor and Windsurf integrate AI deeply into the IDE - not just a sidebar, but a real collaborator.

Wave 03

Autonomous Agents

2025-present. AI systems that independently plan, use tools, test, and deploy. Not one prompt, one answer - but one goal, many steps executed without hand-holding at each stage.

Most teams are still in Wave 1 or 2. Wave 3 is available today and the productivity delta is significant. Each wave builds on the previous - none of them obsolete what came before.

06 / AI Agents

What Is an AI Agent?

A chatbot answers questions. An agent completes tasks. That is a fundamental difference - not a matter of degree.

A chatbot waits for your next message. An agent receives a goal, decomposes it into steps, executes those steps using tools, checks the results, and iterates until done - without waiting for you to prompt each step.

⚑

Goal Understanding

Understands complex goals and independently breaks them down into executable steps.

⚒

Tool Usage

Filesystem, APIs, databases, browsers, terminal - all accessible and combinable.

↻

Iteration

Checks results, corrects course, tries alternatives until the objective is met.

The Agent Loop

01
Goal  Receives and interprets the objective
02
Plan  Decomposes the goal into executable steps
03
Execute  Uses tools to carry out each step
04
Verify  Checks output against the original goal
05
Iterate  Adjusts and repeats until complete
07 / Model Context Protocol

Model Context Protocol - USB-C for AI

MCP is an open standard that defines how AI models communicate with external tools and data sources. One protocol, all tools - no more bespoke integrations for every tool-model combination.

Anthropic published the spec, and the ecosystem has adopted it rapidly. Claude Code, Cursor, Windsurf, and others all support MCP. Your server works across all of them.

Before MCP

  • Every tool required its own custom integration
  • No standardization across agents
  • No reusability between tools
  • Fragmented, proprietary ecosystem

With MCP

  • One protocol for all tools
  • Interchangeable and composable
  • Build once, use everywhere
  • Open, growing ecosystem

Real MCP Server Examples

09 / Multi-Agent Orchestration

Specialized Agents

Each agent has a focused role and clear constraints. Specialization beats generalization when tasks have well-defined boundaries.

△

Architect

Strategic architecture decisions. Read-only access - reviews plans before any code is written. Prevents expensive structural mistakes early, when they're cheapest to fix.

■

Executor

Focused implementation. Works in parallel on independent tasks. Constrained to the smallest viable change - no scope creep, no "while I'm here" additions.

◆

Code Reviewer

Detailed reviews with severity ratings. Finds patterns humans miss when tired or under deadline pressure. Applies consistent standards on every single review.

✓

Test Engineer

Test strategy and TDD. Writes and validates tests automatically. Treats failing tests as signals about implementation quality, not obstacles to route around.

⚠

Security Reviewer

OWASP Top 10, secrets detection, unsafe patterns. Runs on every significant change - not just before release, when fixing issues is most expensive.

★

Verifier

Evidence-based completion checks. Tests passed, no regressions, deployment healthy. Never declares done without proof - no assumptions accepted.

The key insight: agents that specialize and have clear constraints produce better results than one generalist agent trying to do everything at once.

10 / Orchestration in Practice

From Requirement to Deployment

A concrete example showing how agents coordinate on a realistic feature request.

// Requirement: "Add user authentication to the API" 1. Planner → Analyzes existing architecture, identifies auth patterns, maps all dependencies 2. Architect → Reviews plan, recommends JWT + session strategy, flags security considerations 3. Executors → Work in parallel on independent pieces: ├ Agent 1: Auth middleware + route guards ├ Agent 2: User model + database migration └ Agent 3: Test suite + API documentation 4. Reviewer → Checks code quality, security implications, consistency with codebase patterns 5. Verifier → All tests green, no regressions, auth flow works end-to-end, ready to merge

Total time: ~45 minutes for what typically takes 1-2 days. The parallel execution and built-in review loops are the multiplier.

The developer's role shifts: from writing code to reviewing agent output, providing domain context, and making architecture decisions. Higher leverage, same accountability.

13 / Honest Assessment

Honest Limitations

Credibility requires honesty. Here is a clear-eyed view of where AI genuinely helps and where human judgment remains essential.

AI excels at

  • Code generation from clear specifications
  • Writing comprehensive, consistent test suites
  • Documentation that stays current with the code
  • Refactoring and modernizing legacy code
  • Pattern recognition across large codebases
  • Dependency management and security patches
  • Code review - thorough, consistent, tireless
  • Repetitive implementation and boilerplate

AI still needs humans for

  • Architecture decisions with real business impact
  • Business logic requiring domain expertise
  • User research and understanding real needs
  • Product strategy and prioritization
  • Edge case judgment in ambiguous situations
  • Team dynamics and stakeholder management
  • Ethical considerations and value tradeoffs
  • Novel problems without existing precedent

The best mental model: treat AI as a highly capable junior developer - fast, thorough, and tireless, but needing guidance, review, and someone who understands the bigger picture.

14 / Compliance & Governance

EU AI Act: What You Need to Know

Full application from August 2026. AI systems are classified by risk level - and the classification of your development tooling matters.

○

Minimal Risk

Most coding tools fall here. Autocomplete, refactoring, documentation generation. Transparency obligations apply - users should know AI is involved in producing output.

◑

Limited Risk

Agent systems that autonomously deploy or make infrastructure changes. Documentation requirements and human oversight mechanisms are required at this tier.

●

High Risk

Safety-critical software, systems affecting fundamental rights. Mandatory human supervision, complete audit trails, and conformity assessment before deployment.

Three immediate actions: (1) Classify your applications and tools by risk level now. (2) Define policies per risk tier - what is allowed, what requires human review. (3) Establish an AI governance board before August 2026.

The Act doesn't ban AI in development - it establishes accountability. Most development tool usage falls in minimal or limited risk. Get ahead of it now rather than scrambling in 2026.

Key question: does your AI tool make decisions, or assist humans in making decisions? The answer changes your risk classification significantly.

17 / Traceability

Audit Trails & Traceability

AI-assisted development must be as traceable as traditional development. With the right practices, it can be more so.

⎇

Git Integration

Normal workflows apply. Feature branches, pull requests, code review. Every AI-generated change goes through the same process as any human-written code.

✏

Co-Author Tags

AI-assisted commits are marked with Co-Authored-By tags. Full, permanent transparency in Git history about which commits involved AI assistance.

✓

Review Mandate

No AI-generated code merges without human review. The same standard as any contributor - no exceptions for small changes or quick fixes.

Logging Requirements

  • Which model generated or assisted the code
  • Prompt context (sanitized of secrets)
  • Output before and after human review
  • Who approved, when, and what changed

Quality Standards

  • AI-generated code meets the same test coverage bar
  • Same linting, type checking, and security scanning
  • Performance budgets apply equally to all code
  • Documentation required, not optional

A well-implemented AI development process produces better audit trails than purely human development - agents log their reasoning, not just their output.

18 / Adoption Strategy

Adoption: Crawl - Walk - Run

Structured rollout of AI coding tools. Step by step, measurable, controlled. The goal is sustainable adoption, not a failed big-bang rollout.

Month 10+. All teams.

19 / Getting Started

Start Here: Quick Wins

High-value, low-risk starting points that deliver measurable results without requiring full organizational commitment upfront.

Immediate (Week 1-4)

  • Legacy documentation. Point an agent at undocumented code and generate READMEs, inline comments, and architecture notes. No risk, high value.
  • Test coverage. Most codebases have coverage gaps. AI writes thorough test suites faster than humans. Start with the most critical paths first.
  • Code reviews. Add AI review as a first pass before human review. It catches obvious issues so humans can focus on what actually requires judgment.
  • Dependency updates. Automate security patches and version bumps. AI handles the mechanical work; humans approve significant changes.

Medium-term (Month 2-6)

  • MCP servers for internal systems. Connect your ticket tracker, database, and monitoring to your agents. Dramatically expands what agents can complete autonomously.
  • Shared skills repository. One canonical set of conventions every developer's agent inherits. Eliminates "which standard applies?" permanently.
  • AI-assisted incident response. Agents that can query logs, identify patterns, and propose fixes during incidents - when speed matters most.
  • Legacy modernization. Incremental, agent-assisted migration of old systems. High effort traditionally, much more tractable with AI.

Pick one quick win, measure the result clearly, then use that evidence to build the case for the next step. Evidence beats argument every time.
